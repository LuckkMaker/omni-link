# 2026-08-02

## monitor 波形采样率优化调研（对比 plink）

- 核实了 https://github.com/pushk3n/plink（pyOCD 直连 DAP 读内存画波形，PyQt6+pyqtgraph）
- **4500Hz 说法属实**：commit e2d43cd "针对 dap-link V2 bulk升级, 10MHz仅采样模式下达到4500+Hz"，条件是 10MHz SWD + DAPLink V2 bulk + "仅采样"（关闭绘图跑纯采样循环，非 UI 模式开关）
- plink 核心优化手段：
  1. SWD 时钟默认 8MHz（omni 当前 1MHz，差 8-10 倍，是最大瓶颈）
  2. 跨 Block 流水线读取 `_pipelined_batch_read()`：直接操作 AP/DP（dp.write_ap + read_ap_multiple + now=False + dp.flush()），多 Block 命令一次发出，Bulk V2 pipeline_depth=6+
  3. Block 合并激进：merge_gap=65536（64KB），max_bytes: HID 1024B / Bulk 2048B，最小载荷比 20%
  4. 读取计划缓存 `_get_read_plan()`（omni 已有 vars_cache 缓存分组）
  5. `enable_read_cache=False` 保证实时性
  6. busy-wait 高精度节流 `_busy_wait_until`（omni 用 time.sleep，精度差）
  7. 热路径零内存分配：预编译 struct.Struct + numpy ring buffer
  8. 数据全进程内，无 WS/JSON 序列化（omni 有 WS+JSON 开销）
- omni 现有差距（文件级）：
  - pyocd_backend.py:176 `actual_speed = speed if speed else 1000000`（1MHz）
  - monitor_backend.py:41 `MERGE_GAP = 16`（plink 64KB）
  - monitor_backend.py `_read_variables` 逐 group 串行 read_memory_block32，无跨 block 流水线
  - monitor_backend.py:489 `PUSH_BATCH = 8` 固定，WS 消息数 = rate/8
  - monitor.store.ts:212 zustand `[...s.samples, ...pts]` 全量拷贝
- 建议优化优先级：① SWD 时钟提到 4-8MHz 并暴露前端 speed ② 借鉴流水线批量读（AP/DP 层）③ MERGE_GAP 放大+载荷比保护 ④ PUSH_BATCH 动态化/负载减重 ⑤ busy-wait 节流

## 流水线失败根因修复（用户贴日志确认）

- **日志证据**：`WARNING: Monitor pipelined read failed ... 'Apm32f407ig' object has no attribute 'ap'`（3 条 = 3 次采样启动，降级机制正常）
- **根因**：项目自带 APM32F407IG target（python/pyocd/target/builtin/geehy/target_APM32F407xx.py）继承 **CoreSightTarget 而非 CortexM**，没有 `.ap` 属性（CortexM 的 `.ap` 来自构造参数 CoreSightCoreComponent.__init__）；CoreSightTarget 暴露的是 `.dp` + `.aps` + **`.first_ap`**（coresight_target.py:354-358，排序后第一个 AP，单核=AHB-AP#0）
- **修复**：`_pipelined_read` 里 `ap = getattr(target,'ap',None) or getattr(target,'first_ap',None)`，两者皆无才抛 AttributeError → 触发降级
- 测试用例10（模拟无 .ap 有 .first_ap 的 target）全 PASS
- 结论：修复后 bulk 探针（DAPLink V2/WinUSB）流水线才真正启用；HID 探针按设计走串行（plink 同判据），性能也不低于改动前（串行同样吃到 64KB 合并+对齐）
- **用户澄清 + 机制确认**：项目实际未用内置 target_APM32F407xx.py，target 从 DFP 动态导入。pyocd 机制（pack_target.py:535）：`type(subclassName, (superklass,), {__init__: _pack_target__init__})`，无 family 匹配时 superklass=CoreSightTarget，`_pack_target__init__`（433）调 `super().__init__` → CoreSightTarget.__init__ → **有 .dp/.aps/.first_ap，无 .ap**（与报错吻合）。`.first_ap` 是 CoreSightTarget property（coresight_target.py:354），pyocd 内部 pack_target.py:302 也用 `self._target.first_ap` → 上一轮的 ap→first_ap 回退修复对 DFP target 同样有效，无需再改
- **用户新日志确认修复生效**：08:19:45 启动，无 "pipelined read failed" warning

## 采样率实测数据与节流优化（用户测试固件 dsp_wave）

- **用户实测**：设定 1kHz → actual_rate_hz ≈ 500+；设定 5kHz → ≈ 1kHz

## 采样率 5kHz→2.8kHz 后下一步：probe 层直连优化

- **瓶颈分析**：单帧 ~0.36ms 中 USB 往返（DAPLink 单事务 ~0.2-0.3ms）是硬性大头；pyocd dp 层每帧多付 2 次 _select_ap（lock + DP SELECT 命令 + TRACE）是次要可压部分
- **已做（monitor_backend._pipelined_read）**：probe 层直连——单 AP 目标（dp.aps<=1，如 DAPLink+单核 MCU）在 CSW 首次设置（走 dp 确保 APSEL + flush 立即生效）后，TAR/DRW/flush 改用 `dp.probe`（CmsisDapProbe）直连，跳过 dp._select_ap；多 AP 目标保守走 dp（probe 不管理 APSEL）
- **可行性确认**：cmsis_dap_probe.A32=0x0000000c，REG_ADDR_TO_ID_MAP 只取 AP 寄存器 2 位偏移（CSW/TAR/DRW=0x0/0x4/0xC），传完整 AP 地址（含 APSEL）可正确映射，无 KeyError
- **修复**：空分组（total_words<=0）时直接返回不写 CSW（用例5 暴露）
- 测试扩到 12 用例（probe 直连/多 AP 走 dp/空分组），全 PASS

## 自动归一化：变量通道 >1 时启动前自动开启（用户需求）

- store syncChannels 里 `yNormalized = s.variables.length > 1`（变量变化即同步）：2+ 通道自动开启 Y 轴归一化（启动采样前生效），≤1 通道自动恢复共享量程；手动开关可在变量不变时保留选择，变量变化时按数量强制
- typecheck 零新增

## 归一化全局通知 + Min/Max 归一化时禁用编辑（用户需求）

- **全局通知**：store syncChannels 里 yNormalized 状态跨越 0/1 边界变化时，push 全局通知（info 类型，3s autoClose）："Y 轴归一化已开启（当前 N 个变量通道，每通道独立缩放；Min/Max 不生效）" / "Y 轴归一化已关闭（仅剩 1 个通道）"；批量增删不重复通知（仅状态变化触发）
- **Min/Max 禁用**：WatchPanel 订阅 yNormalized，归一化模式下 Min/Max 输入框 disabled + opacity-40 + cursor-not-allowed + title 说明"归一化按通道独立缩放，Min/Max 不生效（关闭后可编辑）"；Y Res 仍可编辑（归一化下生效）
- typecheck 零新增

- typecheck 零新增

## 修复：移除/隐藏变量后归一化未自动关闭（复选框取消勾选场景）

- **根因**：removeVariable 只 filter variables/channels，**未重算 yNormalized**（addVariable 走 syncChannels 会更新，删除不会）→ 取消复选框移除变量后归一化仍 ON/按钮禁用；且判定基于 variables.length 而非可见通道数
- **重构**：新增 helper computeAutoNormalize(prevYNorm, channels)——按**可见通道数>1** 判定归一化，边界跨越时全局通知；syncChannels / removeVariable / setChannel(仅 patch.visible 变化时) 三处共用；非 visible 的 setChannel（min/max/color 等）不碰 yNormalized（保留手动选择）
- 行为：移除/隐藏变量 → 可见≤1 → 归一化自动关闭（通知+按钮可操作）；≥2 强制开启
- typecheck 零新增

## 修正：归一化只自动开启、不自动关闭；按钮禁用条件改为"可见通道>1"

- 用户反馈：删除到 1 个变量时自动解除归一化（不要）；且自动解除后点击归一化又被禁用（体验差）
- **computeAutoNormalize 改"只升不降"**：可见通道 >1 时自动开启（通知），≤1 时**保持当前状态不自动关闭**（删除/隐藏变量后归一化保持，尊重用户选择）；关闭通知移除
- **按钮禁用条件**：ChannelPanel 由 `disabled={yNormalized}` 改为 `disabled={forceNorm}`（visibleChCount>1）；≤1 个可见通道时按钮可操作（可手动开关，不会出现"点开就禁用"）
- 行为：>1 可见 → 强制 ON 禁用；删到 1 个 → 归一化保持 ON（不自动关）、按钮恢复可操作（可手动关）
- typecheck 零新增

## 修复：Commander 路径转换多行复制 bug（用户反馈）

- **现象**：路径转换框复制内容到终端粘贴时，终端出现一大堆重复的 `pyocd> elf D:/...` 命令
- **根因**：`CommandSidebar.tsx:284` 原 `convertedPath = pathInput.trim().replace(/\\/g, '/')` 只 trim 首尾空白，保留中间换行；`<input type="text">` 接受粘贴多行（state 含 `\n`，UI 不显示）；xterm.js `term.paste()` 默认 `\n→\r` 当 Enter 执行 → 一行变多命令
- **修复**：`convertedPath` 改 `pathInput.split(/\r?\n/).map(trim).find(nonEmpty) ?? ''.replace(/\\/g, '/')` —— 只取第一行非空内容
- 改后无论粘贴什么（多行路径、含换行的复制内容），复制/插入 load 都只产生单行
- typecheck 仅 4 个既有错误，本轮零新增
